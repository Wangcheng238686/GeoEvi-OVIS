### 二维重叠窗口的同质化风险（2026-10-25，初步检索）

负责人提出“跨二维重叠窗口实例是否已有很多工作”的质疑。检索支持其担忧：

- SamGeo 官方文档已有 SAM3 重叠 tiles 独立推理与回贴融合：
  <https://samgeo.gishub.org/examples/sam3_tiled_segmentation/>。
- Remote SAMsing（arXiv:2605.00256）直接面向大幅遥感 SAM2 分割，以 contextual
  padding 和 best-match merge 恢复跨 tile 碎片：<https://arxiv.org/abs/2605.00256>。
- CrossCut（AAAI 2026）研究遥感跨 patch 交互分割与点击传播；官方论文说明其基于
  SimpleClick，不能误写为 SAM 原生记忆改造：
  <https://ojs.aaai.org/index.php/AAAI/article/view/37637>。
- OmniSAM 已把重叠 patch 序列接入 SAM2 memory；GPRN（AAAI 2025）已有 SAM visual
  prompts 的图关系推理，后者不等同于原生 memory bank 控制：
  <https://ojs.aaai.org/index.php/AAAI/article/view/32695>。

本轮判断：二维滑窗与跨窗拼接本身创新性不足，图加 SAM 或图加 prompt 的组合也不
自动构成新颖性。二维大图可以作为实验场景，但是否主攻该场景尚未获确认。更具体
的候选动机是：同一实例的多次观察和不同实例的上下文需要不同的记忆访问规则，图
能否改善原生记忆的身份关联、读取对象与错误写入控制。须分别对照普通几何去重、
无图同预算记忆和相同主干微调。当前检索只确认近邻与风险，尚不能宣称图控制 SAM
空间记忆是文献空白；后续还需完整查重和作用空间探针。

## OmniSAM 滑窗记忆的源码级结论（2026-09-29）

`paper-ref` 中这篇工作是 ICCV 2025 的 OmniSAM，作者已经公开官方源码：
<https://github.com/Ding-Zhong/OmniSAM>。它没有设计一种新的记忆网络，而是把同一张宽图
横向裁成重叠的 1024×1024 patch 序列，把 patch 索引当作视频帧索引，复用 SAM2 的
`memory_encoder` 和 `memory_attention`。典型输入宽度和 stride 分别为
2048/128、3072/256、4096/384，均得到 9 个 patch；这是一维横向全景切窗，不是二维
遥感大图遍历。

每个 patch 的 Hiera 最低分辨率特征先读取最近 `n` 个 patch memory，再与中、高分辨率
特征送入固定类别语义 decoder。当前预测取 `argmax` 类别图，与当前视觉特征经 SAM2
memory encoder 编码，`detach` 后按 frame index 保存，供后续 patch 使用；每张新图前
清空 bank。源域训练随机采用正序或逆序，并以 80% 概率启用 memory；目标域/验证分别
跑从左到右和从右到左两遍，两遍之间清空 memory，再把对齐后的 softmax 结果融合。
论文的动态伪标签阶段还要求重叠 patch 对同一像素类别全票一致且最低置信度过阈值，
否则把该像素设为 uncertain。

这项工作的直接价值是给我们提供一个可执行的 **M1 强基线**：切窗序列化、SAM2
memory 读写、逐图 reset、双向扫描和重叠区融合都有现成骨架。它也证明“单张宽图可通过
伪视频方式使用 SAM memory”，论文报告 memory on/off 的代表结果为 62.46/59.34 mIoU，
且 0/3/6/9 个 memory slot 中 9 最好。但它不能直接成为我们的主方法：其任务是固定类别
全景语义 UDA，不是遥感开放词汇实例分割；memory 只按最近处理顺序读取，没有全图坐标、
二维 tile 拓扑、实例 ID、质量写入门控或按关系随机检索。

源码还存在复现落差：论文设置 memory bank=9，但公开 `train.py` 默认 3，
`validation.py` 开启 memory 后也固定为 3；README 的训练示例传入了训练参数类未定义的
`--use_mem_bank`，验证入口还残留空 checkpoint 和作者机器路径。因此可借其内部模块，
不能直接运行 README 命令就宣称复现论文。对本项目最稳妥的使用方式是：M0 独立切窗；
M1 修补后的 OmniSAM 式 FIFO memory；M2 在相同切窗和 memory 预算下，用全图坐标、
tile overlap 与跨窗实例共指图选择写入和读取对象。只有 M2 稳定超过 M1，且对扫描顺序
更不敏感，图空间记忆才构成独立贡献；否则应保留 OmniSAM 基线并放弃图包装。

### 决策：滑窗改造还是图改造（2026-09-29）

当前最合理的选择不是二选一地重写 SAM3，而是区分**工程基线**和**论文方法**：工程上
先复现最小的 OmniSAM 式滑窗 FIFO memory，确认跨窗记忆在真实大图遥感数据上是否有
收益；论文方法则研究由空间拓扑与跨窗实例关系控制 memory 的写入和检索。滑窗只负责
把一张大图变成多次局部观测，不能再作为创新，因为 OmniSAM 已覆盖“patch sequence →
SAM memory”这一命题。

第一版不应修改 SAM3 原生 memory encoder、attention、RoPE 或训练流程。推荐把图放在
模型外部作为轻量 controller：节点保存 tile、跨窗实例观察及其全图坐标、mask、类别
分布和质量；边只表达 tile overlap 与经验证的 instance correspondence；图根据邻接、
共指和质量选择少量可靠 anchor，再通过已有 mask/visual prompt 或公开 memory 接口送回
SAM3。这样既保留现成代码边界，也能用严格对照判断图是否真的优于最近帧 FIFO。

实验按 M0/M1/M2 三层止损：M0 独立切窗融合；M1 同预算 FIFO memory；M2 同预算图选择
memory。若 M1 不优于 M0，说明该数据上的跨窗 memory 没必要，停止 M2；若 M1 有收益但
M2 不优于 M1，保留简单滑窗基线并放弃图创新；只有 M2 稳定优于 M1、降低重复/漂移且
对扫描顺序更稳，才进入更重的 native spatial-memory adapter。当前 V3 的 overlap
competition 图尚未证明独立收益，因此不能把它直接搬来；M2 必须重新定义为跨窗实例
共指与记忆检索图，并重新用大图数据验证。

### 二维滑窗是否应考虑，以及 Slide-SAM 的准确启发（2026-09-29）

真实遥感大图通常在宽、高两个方向都超过模型输入，因此最终大图协议应考虑二维重叠
tile，而不能只沿水平方向复制 OmniSAM。但二维滑窗首先是数据与坐标协议，不等于必须
立刻修改 SAM3 memory：每个 tile 应记录全图 origin、scale、有效区与 overlap，并建立
四邻接或八邻接；蛇形顺序只能作为 FIFO 基线，不能定义空间相关性。

本次找到并下载的医学论文是 MIDL 2024 的 Slide-SAM。它容易被记成“二维滑窗加 SAM”，
但准确机制是把三张相邻二维 CT/MRI 切片堆成一个窗口，只在中心切片给 prompt，同时
预测三片；再把边缘片 mask 形态学去噪、转成 box/point prompt，沿体数据 z 轴向前和
向后传播。它既不是单幅 x–y 图上的二维网格，也没有 SAM2 memory bank；状态通过显式
prompt 传播。因而它不能直接证明二维遥感 FIFO memory 有效，却给出一个更轻的可实现
接口：把可靠邻窗重叠 mask 映射为当前 tile 的 mask/box/visual prompt，再调用现成 SAM3。

二维遥感版应把切片链推广为 tile graph：节点是带全图坐标的 tile/实例观察，边是空间
重叠和跨窗实例共指；一个 tile 可能同时从上、下、左、右收到证据，所以需要质量门控、
冲突融合、双向一致性与停止条件。建议新增中间对照 P1：M0 独立二维 tiles；P1 固定二维
邻接的 mask→prompt propagation；M1 蛇形 FIFO memory；M2 图选择的 prompt/memory。
若 P1 已达到 M2，说明图没有独立价值；若所有跨窗版本都不优于 M0，就停止二维记忆。
该实验只能在保留原始大图及跨 tile GT 身份的数据上进行，不能用已经独立切好的小图
伪造跨窗收益。

### 最终收敛路线：TG-CWP（2026-09-29）

经过 OmniSAM FIFO memory、Slide-SAM 邻窗 prompt propagation、原生 memory 改造与图
控制方案对比，后续大图主线只保留一条：**二维拓扑引导的跨窗正框提示传播**
（Topology-Guided Cross-Window Prompting，TG-CWP）。v3 类别重排只完成已登记的独立
验证，不再叠加滑窗或 memory；新路线单列为 v4，设计与实施分别见
`notes/design-v4.0.md` 和 `notes/implementation-v4.0.md`。

TG-CWP 采用两遍、非递归流程。第一遍对所有二维 tile 独立运行 text-only SAM3；再在
全图坐标系建立候选观察图，只连接空间相邻 tile 中经重叠区域验证的同类别实例观察，
从每个实例簇选择一个最完整、远离边界且高质量的 anchor。第二遍只把 anchor 的重叠
mask 外接框映射到缺失或截断的目标 tile，通过项目已经验证的
`add_geometric_prompt(..., label=True)` 与同类 text prompt 联合重跑。第二遍输出不再
传播，从而控制错误级联并消除扫描顺序依赖。

这条路线明确砍掉：SAM3 原生 memory/attention/RoPE 改造、mask prompt、负 prompt、
蛇形 FIFO 主方法、GNN、LoRA/adapter、类别共现和跨图长期记忆。图只负责二维邻接、
跨窗实例共指与可靠 anchor 路由；实际反馈走已经可用的正 box exemplar 接口。论文的
核心可证伪命题是“关系选择是否比固定邻接传播和等预算随机选择更好”，而不是泛称
二维滑窗或图有效。

唯一对照链为 C0 独立 tiles、C1 固定邻接正框传播、C2 TG-CWP 图选择、C3 等预算随机
anchor。C1 不优于 C0 即停止整个跨窗方向；C2 不优于 C1/C3 即放弃图贡献；只有 C2
在未参与规则选择的大图上稳定领先，才进入后续主实验。该路线必须使用保留原始大图、
全局坐标和跨 tile GT 身份的数据，不允许将独立小图人为切碎制造收益。

## 当前探针意图与已知结论：简明口径（2026-09-28）

我们要验证的核心问题很窄：SAM3 已经在同一物体位置生成多个异类解释时，用该候选
自己的图像 crop 比较“它更像自身类别，还是更像竞争类别”，能否把错类候选降分，
同时尽量不伤害正确候选。固定所有候选和 mask，只改变排序分数；因此探针不负责找回
没有候选的目标，也不证明完整系统或图记忆有效。

已知结论分三层：第一，T1 已证明跨类冲突确实存在，RemoteCLIP 有类别判别信号，
并且 margin 能形成压错多、误伤少的有利方向，值得进入正式排序实验。第二，修复后的
T2 开发集 segm AP 显示独立 CLIP 融合 B1 仅比 SAM3 B0 高 0.188 mAP 点，局部空间
竞争 B2 比 B1 高 0.282 点，说明相对类别证据有弱正信号。第三，正确补算的非空间
对照 B3 比 B1 高 0.356 点，反而比 B2 再高 0.074 点；所以当前证据不支持“空间关系
或实例图带来独立收益”，更像是一般的同图类别对比重排在起作用。

当前尚不能进入 T3，也不能宣称 V3 有稳定测试集收益：开发增益低于预期，B3 优于
B2，而且还没有未参与选参的源图验证结果。下一步只做一次冻结参数的独立源图验证；
若 B3 仍不低于 B2，就停止图/空间关系主张，转向更简单的类别对比重排；若 B2 不能
稳定超过 B1，则连当前相对惩罚机制也停止。

### 当前“图”的定位与作用（2026-09-28）

当前的图不是复杂 GNN，也不负责传播分数、补目标或生成 mask。它只是一个**稀疏的
候选关系结构**：每个 SAM3 候选是节点；两个不同类别的候选若 mask 在同一位置高度
重叠，就连一条 `competition` 边。边的作用是限定“当前候选应该和哪些类别解释做
相对比较”。因此图在 V3 中本质上是证据路由和干预门控，而不是预测主体。

它原本希望通过三件事辅助开放词汇实例分割：第一，把“同一物体被船/汽车等多个词
重复解释”的冲突显式找出来；第二，只在存在直接竞争边时使用类别反证，避免全图无关
类别随意改分；第三，保留候选、mask 和开放词汇能力不变，只把更可能错误的类别解释
向后排序，从而提高实例 segm AP。图不能解决无候选漏检、背景误检或 mask 质量差，
也不能凭关系创造新实例。

但当前证据只支持前两项是合理设计意图，尚未证明第三项中的“空间图门控”有独立
收益。开发集上，不使用空间边、只在同图预测类别间做比较的 B3 比使用重叠边的 B2
更好。这说明现有 overlap 图可能过窄，漏掉了有用类别对比；也可能说明真正有效的是
crop 的多类别语义比较，而不是图。故当前图应定位为**待验证的局部竞争选择器**，
不能定位为已成立的论文主贡献。只有独立验证中 B2 稳定超过 B1 和 B3，图才升级为
必要组件；否则应删除图包装，收敛为更简单的类别对比重排。

### 遥感模型中图的常见定位，以及与本项目的差别（2026-09-28）

遥感领域引入图，最常见的定位是**关系归纳偏置**：把像素、超像素、地物区域、实例、
时相或语义概念作为节点，把空间邻接、光谱相似、几何方位、跨尺度对应、时间变化或
语义关系作为边，再通过邻居聚合补充单节点看不到的上下文。典型用途可以归为五类：

1. 空间/拓扑建模：道路连通、建筑邻接、地块边界、目标方位等关系约束局部预测，
   主要解决 CNN/Transformer 特征有上下文却缺少显式拓扑的问题。
2. 区域与实例上下文推理：对象节点通过邻接、包含、共现或相对位置交换信息，用于
   场景理解、指代分割和细粒度类别消歧。
3. 光谱—空间、跨尺度或多模态融合：不同波段、patch、尺度、传感器或图文实体作为
   节点，边决定哪些信息允许融合，避免所有特征无差别混合。
4. 时序/变化与记忆组织：多时相影像、帧或历史观测作为节点，图负责关联同一地物、
   聚合稳定证据并抑制噪声记忆。
5. 语义/知识结构：类别、本体概念和实例形成图，以类别层级、属性或语言关系帮助
   开放词汇理解，但需要防止固定知识先验压制未知类别。

这些模型中，图真正应购买的是“**边所携带的额外信息**”：去掉边但保留相同节点和
特征后，结果应明显下降；否则图只是换了一种张量组织方式。MRSNet 的 GCN 属于空间
关系建模，GMN 属于图化记忆读写，3DGraphLLM 属于实例语义关系编码；三者的图分别
承担上下文聚合、记忆管理和关系 tokenization，而不是单纯给候选画连线。

本项目当前 V3 属于上述第二类的最小版本：节点是 SAM3 实例候选，边只有“异类 mask
直接重叠”的 competition 关系，图只选择要比较的类别，不做学习式消息传递、拓扑
约束或记忆管理。它的优点是轻量、可解释、不会改 mask；缺点是边的信息量很少。
开发集上 B3（没有空间边）优于 B2，正说明当前边尚未买到额外信息。因此不能因为
遥感领域常用图，就保留图作为预设贡献；必须由 B2−B3 证明重叠关系确实比普通类别
对比更有用。若验证仍失败，最合理的收敛不是堆 GNN，而是先采用无图类别对比；只有
发现单 crop 无法表达、而邻域/几何/跨窗口关系确实能稳定纠错时，才重新定义更有信息
含量的边。

### 应定位为实例关系图，还是空间拓扑图（2026-09-28）

就当前 V3 的真实实现而言，**“空间约束的实例关系图”比“空间拓扑图”准确**。节点是
SAM3 产生的候选实例，不是规则网格、地块、道路或 tile；边表达两个异类实例候选在
同一位置竞争，空间重叠只是建边条件，边的语义仍是实例间的类别冲突。因此更严格的
名称应是“局部实例竞争图”或“空间门控的实例关系图”。

“空间拓扑图”通常要求图本身保存并利用空间结构，例如 tile 邻接与重叠、对象相对
方位、包含/接触、道路连通或跨窗口对应，并且这些拓扑关系参与聚合、检索或一致性
约束。当前只有 mask IoU≥0.5 的一类边，没有二维邻接骨架、方向、多尺度或跨窗口
拓扑，直接称空间拓扑图会扩大实际贡献，也无法由现有 B2 实验支撑。

推荐采用分阶段定位：当前论文机制若验证成功，称“空间门控的实例关系重排”；只有
未来大图/滑窗方案真正加入 tile 拓扑、跨窗实例对应与多关系边，才能升级为“空间
拓扑—实例关系双层图”。但命名不能替代实验证据：目前 B3 高于 B2，说明连“重叠边
是必要的实例关系”都尚未成立。若独立验证仍如此，应去掉图主张，称为同图类别对比
重排；不能通过改名为空间拓扑图来保留图贡献。

## V3 T2 dev sweep 审计（2026-09-28）

结论：**本轮 sweep 无法作为 T2 科研结论，不能据此冻结参数或进入 T3。** 它证明
端到端候选生成和批量导出已经跑通，但实际执行的 B2/B3 打分与登记公式不一致，
评测又是 bbox AP 而不是任务要求的实例分割 segm mAP。现有结果应标记为失效的
工程联调，不应被解释为“局部图关系有效/无效”。

现有产物覆盖 iSAID train 的 15 个源图组、237 个切片、8,571 个 GT，固定输出
23,810 个候选；manifest 在推理前生成，候选数量在各变体间一致，这些基础纪律是
成立的。独立复算也能精确复现 `eval_results.json`：B0 bbox AP=0.319666，
B1(beta=0.5)=0.323428，表中所谓 B2 最优为 0.324076，B3 最优为 0.324240。
但这些小数不能用于方法判断，原因如下。

1. `run_t2_dev.py` 在候选循环结束后才生成网格，却在 B2/B3 公式里使用循环外残留的
   `z_own`，而不是当前候选的 `c["z_own"]`；同时所有 beta 都复用固定 beta=0.5
   算出的 `u`。因此三个 beta 的 B2/B3 文件逐字节相同。40 个输出文件实际只有
   11 组不同内容，beta 网格没有真正执行。
2. runner 自己复制了一套公式，没有调用已经有单元测试的 `scoring_v3.py`，所以
   `test_scoring_v3.py` 虽然通过，也没有覆盖实际 sweep 路径。这是错误逃过验收的
   直接原因。
3. B3 的登记定义是“同图其他**预测类别**，但不限制空间重叠”；runner 实际拿
   全部 15 类词表竞争，包括该图根本没有候选的类别。237 图中只有 198 图产生候选，
   这些图各自仅出现 1–9 个预测类别，没有一图出现全部 15 类，因此当前 B3 不是
   设计中的无空间关系对照。
4. 输出只保存 tight bbox，没有保存实例 mask。`eval_results.json` 的数字可由
   COCO bbox evaluator 精确复现，不能冒充 segm mAP。未提交的 `t2_dev_eval.py`
   又在构造内部检测记录时漏掉 bbox，实际执行会在 `d["bbox"]` 处报 KeyError；
   仓库中也没有能够复现 `eval_results.json` 的正式评测入口。
5. 本轮只有开发组，没有 implementation-v3.0 要求的独立源域验证组，也没有配对
   bootstrap、逐类/尺寸损益或错类/背景/TP 分账。即使实现无误，单次 dev 最优也
   只能选参，不能决定进入 T3。

因此不要解读当前表中 B3 比 B2 高 0.00016、B2 比 B1 高 0.00065 的差值；它们既
低于预登记的 1 个 mAP 点量级，又由错误公式和错误评测产生。当前下一步不是扩大
模型或上测试集，而是先让 runner 在一次推理中持久化固定候选的 mask、候选 ID、
原始分数和 RemoteCLIP 全类分数，再把 B0–B3 改成纯离线重算，并以同一批真实 mask
计算 segm mAP。当前产物没有保存 mask/特征，故这一步仍需重新跑一次候选推理；之后
的参数网格不应重复调用 SAM3/RemoteCLIP。
修复版先按协议用 dev 选 beta，再固定 beta 选择 delta/lambda；随后只在未用于选参的
源图组验证一次。若验证集 B2 不优于 B1，停止当前相对惩罚；若 B2 不优于正确的 B3，
即便总 AP 上升也不能把收益归因于空间关系。

## 用直白的话说：我们在做什么（2026-09-10）

把项目想成“从遥感图里按名称找东西”。你给系统一个类别词，例如“飞机”，它应当
把每架飞机都圈出来；既不能漏掉，也不能把船、球场、背景错说成飞机。SAM3 是负责
先广撒网找候选的基础模型。我们没有在训练它，而是在研究能否用图像中的额外线索，
把它找出的候选重新排好顺序，让真的目标排在前面、假的排在后面。

最初的 v2 方案很大：候选之间互相支持、互相竞争，还加入场景、上下文、完整性和
合并规则。它在 NWPU 的完整试验中失败了：最强的无边对照 A1 是 24.75 mAP，
完整图 A2 只有 15.51 mAP。意思不是 SAM3 没有候选，而是我们那套“多条关系一起
推理”的重排把原本相对正确的排序弄坏了。因此 v2 已停线，不再往上叠加训练、记忆
或 exemplar 模块。

现在的 v3 把问题缩到最小：**同一个位置同时像两种类别时，拿同一个小裁剪分别问
“它更像飞机还是更像船”，能不能只给较弱解释降分？** 不增新 mask，不改类别，
不强制删除候选；它只是测试一条很窄的“局部跨类比较”规则是否有独立价值。

我们正处在 v3 的 **T1 检查阶段**，尚未到真正比较新方法效果的 T2。T1 的任务是
先确认这条规则值得做：现实候选中是否真的有可利用的跨类冲突；它能否多压低错类
候选、少伤害真候选。现有探针给出了一点希望（设 margin 后表面上错类受影响更多），
但实现把整图当作候选 crop、并混入背景误检，结果不可作为决定依据。因此不是“方案
失败”，也不是“已经通过”；准确状态是 **发现了值得修正后复测的信号，正在补齐这
个准入检查**。

接下来的顺序很简单：修正探针 → 在源域开发/验证划分上重新测真实候选 → 若错类
下降明显且真目标损失可接受，才实现 B0/B1/B2/B3 的正式对照并看 mAP；若仍没有
这个取舍，就停止 v3，而不是继续加复杂模块。最终目标不是让方法看起来复杂，
而是得到一个能经得起对照实验的结论：局部跨类证据到底能不能稳定改善遥感开放词汇
实例分割。

### 待决策：借鉴 SCORE 的区域上下文（2026-09-10）

负责人提出用 SCORE 的区域上下文辅助 ship/vehicle 消歧。该方向有明确依据：SCORE
用预测 mask 膨胀，在膨胀区域内池化 RemoteCLIP 最后层 patch 特征，再经**训练得到**
的 Transformer 注入实例类嵌入；其定性结果正展示 ship 被误判 vehicle 的纠正，区域
上下文也优于整图 CLS。但它不是“把环带特征直接加到 CLIP 分数”：SCORE 全程训练
Mask2Former、可学习膨胀和注意力投影；其消融还显示无训练的 add/concat 会退化。

因此有两个不同的研究方向，不能混为同一改动：一是保留 v3 training-free 边界，
只把“候选内/周边区域”作为冻结编码器的可比较证据并新设对照；二是接受训练式
SCORE 风格 adapter，重开设计版本、训练/开发划分和与 SCORE 的新颖性边界。当前
不自动选择，也未实现任何上下文改动；先由负责人决定边界，再继续压力测试与设计。

### 终态架构与论文形态：当前可说与不可说的部分（2026-09-10）

当前**没有已经冻结的“终极架构”或可承诺的论文创新点**。v2 的终态曾设想：SAM3
候选 → 同图实例/环带/场景/unknown 的证据图 → 联合重排与完整性诊断 → 可靠候选
作 self-exemplar 再调用 SAM3。这个架构已在其第一道、最关键的“图独立增益”检验中
失败，因而图传播、完整性进入排序、学习化、self-exemplar 都不能再当作既定主线或
论文贡献。

若 v3 的最小机制和 SCORE 式区域证据先后被验证，一个合理的**候选终态**会是：

```text

  → 仅对重叠的异类候选，比较同一候选区域的类别证据
  → 受门控的局部上下文适配/相对重排
  → 输出不改 mask、不凭上下文造新目标的实例排序
```

它的潜在论文主张应收敛为一个可证伪命题：**“在冻结 SAM3 的开放词汇遥感实例池中，
对象周边的区域语义能在局部跨类冲突时提供可靠的反证，从而改善细粒度错类排序，
且不靠全局场景偏置或候选传播放大误检。”** 创新不应宣称“首次使用上下文/图/CLIP
或 SAM3”——SCORE 已有区域+全局上下文，SAM3 已有概念分割。可争取的差异是：
冻结候选的实例级、局部竞争条件下的反证式重排；上下文只在有竞争时门控介入；
用 B0/B1/B2/B3 和错类/背景/TP 账本证明它的因果增益与安全边界。

但若区域上下文需要一个训练 adapter 才有效，论文就变成训练式方法：候选区域构造、

### 实例关系图在当前任务中的定位（2026-09-10）

实例图“联合重排消歧”在逻辑上**有条件合理**，但不是开放词汇分割的天然正确答案。
SAM3 对每个类别独立产生候选，同一物体可被多个类别重复解释；若两个重叠候选之间
有额外、可靠且带方向性的条件证据（同一小区域更像 ship 而非 vehicle，或周边区域更
符合港口/水面而非道路），一条局部竞争边可补足单候选分数的盲点。这是图的正当角色：
把“谁在和谁竞争、证据比较发生在哪个区域”显式化，而不是让所有候选互相投票。

然而图不能解决候选池没有真目标、背景假阳性、mask 定位错误或类别本身不可分等问题。
现有统计中背景候选数量很大；即使错类边完全正确，也不保证 mAP 上升。更重要的是，
v2 的全图推理已经显示反例：支持传播、概率或和全局风险把 A1 24.75 mAP 降至
A2 15.51，说明“多关系联合推理会提升”在本项目上已被否定。图只应保留稀疏、直接、
不抬分的局部竞争关系；上下文必须作为可检验的反证，不能当作无条件支持票。

因此当前 v3 若只做“同一候选 crop 对直接重叠的异类文字进行 max 比较”，严格说更
像**局部竞争条件重排序器**，而非足以单独主张的图模型。只有在后续证明：相对局部
关系 B2 优于独立 B1，且优于不用重叠关系的 B3，并且某种多节点/多边结构进一步优于
同等局部 ranker 时，才有资格把“实例关系图”作为论文主贡献。否则论文应诚实收敛为
区域上下文驱动的局部跨类消歧。

对指标的预期不应预先许诺涨点。合理的先验是：船/车、车辆细分类、运动场等高混淆
子集可能受益；背景为主、无正确候选或合法包含关系的样本可能无益甚至受害。继续
条件只能由冻结开发/验证集的 COCO mAP 与错类/背景/TP 分账决定，而不是由图形式或
单个案例决定。当前探针尚无效，故没有可信的正向 mAP 预期。

## 1. 一句话目标（v2 历史说明）

给定遥感图像和任意类别文字（如 `airplane`），输出图中该类别每个独立实例的
mask。项目以 SAM3 的 text-only 实例发现为基础，再用同图候选、局部区域和场景的
关系来判断哪些结果可信、重复、冲突或可能不完整。

## 2. 为什么需要这条路线

SAM3 能从文字产生候选实例，但遥感图像中容易出现相似类别混淆、重复候选和大量
误检。P0 全量基线表明：候选召回足够进入后续研究（三集池化类均召回 0.5742，超过
GO 阈值 0.40），但误检占失败案例 87.6%。因此主问题是候选排序/消歧，而不是重新
训练一个分割器或单纯精修 mask。

## 3. 方法的直观流程

```text
图像 + 类别文字
  → SAM3 text-only 产生候选 mask
  → 建立“证据图”（候选、类别、局部区域、场景、unknown 的关系网络）
  → 用关系证据重新评估候选、合并重复、报告不完整风险
  → 输出最终实例结果
  → 可选：选择可靠候选作 visual exemplar，交给 SAM3 再分割
```

证据图不是新的分割器，不能凭上下文硬造实例。它只组织和使用已经存在的候选与
证据；text-only 是主结果，GT/self exemplar 是后续单列报告的增强模式。

## 4. 证据图中有什么

- 节点：查询类别、SAM3 候选实例、候选周边环带、全局场景、unknown；exemplar
  节点留给 P3。
- 文本—实例边：SAM3 分数与候选 crop 对类别文字的 CLIP 相似度。
- 同类支持边：候选外观相似或尺度接近。
- 相似类别竞争边：相近类别的候选若空间重叠，则记录竞争。
- 局部上下文边：候选周边的高置信类别结合训练集共现先验，作为软证据。
- 场景边：机场、港口、城市等图像级场景仅作为软分数。
- unknown 冲突边：低文本分且输给竞争类别的候选被标为不可靠。

所有初始阈值与权重均登记在 `sam3_ovis/docs/graph-thresholds.md`，不按结果回调。

### 阈值的依据与证据等级

当前 P1 是 training-free v0，阈值分三类，不能把它们都理解为“已经最优”。

| 类别 | 当前值举例 | 依据 | 证据等级 |
|---|---|---|---|
| 协议/评测继承 | 候选池原始 score ≥ 0.05；IoU 0.5；P0 GO 召回 ≥ 0.40 | P0 推理与评测预登记、COCO/实例匹配惯例、SCORE 已发表最弱基线参照 | 较强；固定以保持可比性 |
| 复用已有登记 | 高置信 `norm_text ≥ 0.5` | 复用 S3.2 局部上下文的高置信地板，避免为 S3.3 新增自由参数 | 中等；一致性选择，不是经调优最优值 |
| 启发式初值 | 文本/CLIP 权重各 0.5、竞争 top-K=5、文本相似 ≥0.50、竞争 IoU ≥0.30、尺度比 K=3、环带半径 0.25×sqrt(area) | 可解释的对称起点、几何邻近尺度和稀疏关系控制；在看 P1 指标前登记，防止事后调参 | 较弱；等待 S3.5 消融验证 |

共现先验本身来自 iSAID/SIOR 训练集统计，并使用拉普拉斯平滑；但其 floor=0.01
仍是避免零权边的工程性下限。当前没有用 SCORE 测试集标签搜索这些启发式参数，因而
P1 的结论不是“这些数字最优”，而是“在预先固定、可复现的合理起点下，证据图是否
值得继续”。若 S3.5 显示某项敏感，应把敏感性/消融结果写入报告；若需要改主定义，
应新建设计/登记版本，而不是回改历史阈值。

## 5. 完整性判断是什么

完整性不是 mask 边界质量，而是“该类别当前的候选集合是否看起来混乱或不完整”。

- ECR：高置信候选覆盖了全部候选区域的多少面积。
- URD：低置信候选中，有多少未被高置信候选解释为重复。
- CCR：有多少候选存在跨类竞争或同类重复冲突。
- R：三项症状的等权不完整风险分。

R 在后续只调制置信度和触发告警，不新增或删除实例。它对“完全没有候选”的漏检
没有感知能力，因此不能替代 P0 的召回评测。

## 10. 若将实例图与 SAM3 原生记忆结合，应如何定义创新（2026-09-10，待立项）

先区分两个容易混淆的概念。当前 v3 在静态图像的固定候选池上做局部跨类比较，
它既没有调用 SAM3 tracker，也没有读写 SAM3 的时序 memory bank；因此它只能称为
候选重排序，不能包装为“图记忆”。SAM3 原论文中，detector 负责逐帧发现，tracker
通过记忆库延续单个对象的 masklet；记忆本质上服务于该对象的时序连续性，基础形式
中不同对象之间没有显式关系推理。

若重新立项，合理的命题不是“给候选加一个图”，而是：**以关系图作为 SAM3 记忆的
控制层，使原本孤立的对象记忆成为可选择、可校验、可检索的关系化记忆。** 图必须在
下列至少一项中真正起作用：

- **写入**：决定哪些高质量 detector/tracker 观测可写入，避免不确定自预测污染记忆；
- **保留/刷新**：依据身份一致性、竞争冲突、时空连续性和新颖性，决定保留、冻结、
  淘汰或要求 detector 重新提示；
- **检索**：当前候选只读取与其身份、邻域、类别竞争相关的小子图，而不是盲目汇集
  所有历史对象；
- **再提示**：图输出的是可审计的证据选择、记忆检索或 refresh 决策，SAM3 tracker
  仍产生最终 mask，而不是由图直接“投票造 mask”。

一个最小可辩护架构为：SAM3 detector/tracker 生成带质量、位置、时间/瓦片坐标、
开放词汇证据与 masklet 表征的记忆记录；记录构成稀疏异构图，边只表示经门控验证的
同一实例延续、空间邻接/包含、局部上下文一致或跨类直接竞争；图控制器执行
write–retain/refresh–retrieve 三步；检索结果作为 tracker 的记忆选择或 detector
重提示依据。这样，图的贡献是“**让记忆在何时、为谁、凭什么被使用**”，而非 v2 中
已经失败过的无差别消息传递和误检互相抬分。

可检验的创新候选有三层：

1. 从“每对象彼此独立的 masklet 历史”提升到“对象—关系—上下文联合的记忆组织”；
2. 把关系用于记忆生命周期（写入、刷新、淘汰、读取），而不只是末端 score fusion；
3. 用不确定性与 detector refresh 约束关系传播，防止错误被长期记忆化。

这只是**创新假设**，不能提前声称“首个”或“必然提升”。它要成立，实验至少应包含：
原生 SAM3 memory、同预算的无图 memory controller、只做末端重排序、完整图控制器；
并报告身份保持、遮挡/相似类别后的恢复、长序列漂移和最终 mAP。若图只优于 raw
score，却不优于同预算的无图记忆控制器，贡献应降格为重排序而非关系记忆。

任务边界也必须先作选择。对真实视频或多时相遥感序列，SAM3 的时序记忆有原生语义，
上述命题最干净；对当前 SCORE 静态单图，强行把重叠瓦片排成“伪时间序列”是新的空间
记忆假设，必须额外验证遍历顺序不敏感、相邻瓦片确有可迁移信息，不能把它当作原生
SAM3 memory 的既有能力。若继续只做静态单图 v3，则应诚实地保留“局部竞争重排序”
的定位，而不使用图记忆的表述。

### 10.1 上下文、节点、关系与开放词汇记忆的含义（2026-09-10，设计说明）

**上下文不是一个“背景类别实例”，也不应直接给对象加分。** 对实例 (i)，上下文是
与其空间绑定、但不要求可实例化的一组条件证据：局部环带/相邻区域的视觉 token，
可选的场景区域 token，以及稳定的相邻对象记录。它回答的是“这个对象在这里、此刻
是否仍像它自己”，而不是“画面中是否存在某个类别”。因此，上下文只能经过可靠性与
相关性门控后影响记忆的读写；不能以共现先验或全图场景直接硬推某一开放词汇类别。

建议从小而可审计的异构图开始，避免 v2 那种把所有候选与证据全连接的大图：

| 节点 | 保存的信息 | 用途 |
|---|---|---|
| 对象记忆节点 (O) | masklet/对象表征、开放词汇类别分布、位置、时刻、质量、是否在场 | 记忆读写的主体 |
| 当前查询节点 (Q) | 当前帧/瓦片的候选 mask、图像特征、文本相似度与不确定性 | 发起检索、接受决策 |
| 局部上下文节点 (C_l) | mask 外环带或邻接区域的压缩视觉表征、坐标与尺度 | 判断局部环境是否支持对象身份、跨视图对应 |
| 场景节点 (C_g)（可选） | 全帧/大区域的压缩特征，非类别标签 | 只作检索路由或异常检测，不直接分类 |
| 类别语义节点 (T)（可选） | 当前 prompt 的文本表征或类别原型 | 记录开放词汇证据的来源；不将未知类强行归入已知节点 |

关系必须稀疏、方向明确，并带置信度和时间/空间有效范围：

| 边 | 连接 | 条件与作用 |
|---|---|---|
| `temporal-identity` | (Q/O_t \leftrightarrow O_{t-1}) | mask/外观/运动或重叠瓦片一致；供对象记忆检索与延续 |
| `context-anchor` | (O,Q \leftrightarrow C_l) | 对象和其环带/邻域的绑定；检验跨帧或跨瓦片时上下文是否稳定 |
| `spatial-relation` | (O_i \leftrightarrow O_j) | 邻接、包含、相对方位等可观测几何，不把统计共现当成事实 |
| `competition` | (Q/O_i \leftrightarrow O_j) | 同一区域、不同开放词汇假设且直接重叠；用于触发复核或抑制错误写入，不能互相抬分 |
| `semantic-evidence` | (O,Q \leftrightarrow T) | 文本—图像相似的带不确定性证据；未知/低置信应允许不连接或连至 unknown |

“图决定记忆生命周期”具体是四个可观察动作，而不是抽象的 message passing：

1. **write**：当前候选只有在对象身份一致、局部上下文不矛盾、且没有强竞争冲突时，
   才能写进长期记忆；否则暂存为短期假设或丢弃。
2. **retain / evict**：重复、陈旧或已被高质量 detector 观测替代的记录被压缩或淘汰；
   置信低但尚未被反证的记录冻结，不能持续影响之后的对象。
3. **retrieve**：对当前候选只读取相关对象的历史、其绑定上下文和必要的竞争者，而不
   读取整帧所有类别；读出的作用是选择 SAM3 memory、校验身份或安排重提示。
4. **refresh**：关系冲突、上下文突变或记忆漂移时，不强行沿用历史，而是调用 detector
   重新发现并用新观测替换旧记忆。

这对开放词汇分割的特殊意义在于：类别名称并非封闭标签，文本相似度也常在相近类别
间摇摆（如 ship/vehicle、building/road）。图不应以训练集的固定类别共现“裁决”未知
类别；它应保存并检索**可迁移的对象证据与上下文证据**，在新的 prompt 出现或旧 prompt
不确定时，决定是延续、延迟写入、召回 detector，还是保持 unknown。由此预期改善的
是长时/跨视图的类别漂移、重复发现和错误累积，而非凭空补回 detector 从未提出的对象。

最小对照应拆开验证：对象单独记忆 vs 对象+局部上下文但无对象关系 vs 完整稀疏图；
同时报告开放词汇 mAP、未知/相近类别混淆、身份延续/漂移率和错误记忆写入率。只有完整
图在同等记忆预算下超过前两者，才能把上下文与关系称作独立贡献。

### 10.2 为什么单幅遥感开放词汇实例分割仍需要空间记忆，以及完整 pipeline（2026-09-10，重新核对 OmniSAM 后）

此前把记忆的合理性只归于真实时序，是不完整的。`papers/README.md` 中的 **OmniSAM
（ICCV 2025）** 已给出直接先例：将一张全景图切为重叠 patch、视作伪视频并复用
SAM2 memory attention，以跨 patch correspondence 提高预测一致性；其 memory on/off
消融为 62.46/59.34 mIoU。故“空间序列化 + 记忆”是成立的单图范式。但它已是先例，
不能作为本文创新本身；而且它做的是固定类别全景语义 UDA、链式 FIFO patch memory 和
一致性伪标签，不是遥感开放词汇实例级记忆管理。

对**大幅单张遥感开放词汇实例分割**，记忆管理的必要性来自三件事共同出现，而不是
“开放词汇天然需要记忆”：

1. 整图通常不能一次送入模型，滑窗使同一真实对象和其环境被多个不完整视野反复观察；
   对象在窗边被截断、相邻窗口重复检出、不同窗口看到的上下文不一致；
2. 开放词汇类别由图文相似度决定，局部 crop 的类别证据更容易摇摆；同一目标在一个
   窗口像 `ship`、另一个窗口因截断或背景像 `vehicle`，而已有类别词未必覆盖真实对象；
3. 直接累积所有历史预测会把上述摇摆固化并放大。因此需要的不是“更多历史”，而是
   有选择地保存多视角观察、拒绝低质量自证据、并在当前窗口仅取回相关证据。

空间记忆解决的是“同一幅大图的有限 FoV 造成的证据碎片化”；开放词汇决定它需要保存
的不只是 mask，而是**对象外观、文本匹配的不确定性、尺度/坐标和局部上下文**。它不
会凭空找回 detector 从未提出的对象，也不能把共现统计当作未知类别的判决规则。

建议的完整 pipeline 如下（以单幅大图为一个独立 episode；测试图之间不共享在线实例
记忆，避免信息泄漏）：

```text
大幅遥感图 I + 开放类别 prompts P
        ↓
1. 坐标感知的重叠滑窗：产生 tiles，并预先建立二维 overlap/邻接拓扑
        ↓
2. SAM3 局部感知：每个 tile 由 detector 产生候选 mask、视觉/对象表征、
   presence/quality、多文本相似度；首次观察不立即成为长期可靠记忆
        ↓
3. 图化的空间工作记忆：把 tile、候选观察、局部环带上下文、prompt 语义
   建成稀疏异构图，并把重叠窗口中同一物体的多次观察关联为一个 instance tracklet
        ↓
4. 图控制器：针对下一个 tile/query，检索「重叠或相邻 tile + 同一实例历史 +
   局部上下文 + 直接竞争类别」的有限子图；执行 write / hold / merge / evict / refresh
        ↓
5. SAM3 记忆读取与重提示：把被选中的高质量邻窗 masklet/对象记录作为 tracker
   memory 或 visual/mask prompt；冲突或低置信时调用 detector refresh，而非沿用旧预测
        ↓
6. 全图实例融合：依据 graph 的跨窗 identity 合并同一对象；跨类竞争只阻止错误写入、
   触发复核或保留 unknown，最终以 SAM3 mask 和校准后的开放词汇证据输出
```

第 3 步的图至少应有四类节点：tile/区域上下文节点（坐标、尺度、全局/局部特征）、
候选观察节点（某 tile 中的一次 mask 观测）、实例 tracklet 节点（跨 tile 的同一物体
暂存身份）和 prompt/类别语义节点（文本表征与不确定性）。边也应是可观测、稀疏的：
tile overlap/邻接边、观察—tracklet 的共指边、对象—环带的 context-anchor 边、对象—
文本的语义证据边、以及仅在同区域异类候选间建立的 competition 边。场景/共现不作为
硬类别边，至多充当检索条件或低权重的软证据。

第 4 步是相较 OmniSAM 的关键：OmniSAM 的 FIFO 序列默认“刚处理的 patch 最相关”；
遥感窗口是二维网格，一块窗口可以同时与上、下、左、右及远处重访的对象相关，FIFO
既会漏掉空间上相关但处理较早的证据，也会读入空间无关的最近窗口。图的价值是以坐标、
重叠、实例身份和不确定性路由记忆，而非以处理顺序路由记忆。

建议分两层实施，避免第一版过大：

- **M0，必要基线**：SAM3 每 tile 独立检测 + NMS/融合，无跨窗记忆；
- **M1，OmniSAM 对照**：固定蛇形扫描、FIFO 的跨窗 SAM3 memory；验证空间 memory
  对当前任务是否有正信号；
- **M2，我们的最小方法**：同一记忆预算下，用 tile-overlap + instance tracklet 图替代
  FIFO；只实现质量门控 write、子图 retrieve、跨窗 identity merge 和 detector refresh；
- **M3，完整方法**：再增加局部 context-anchor 与不确定性 hold/unknown，验证它们是否
  专门降低开放词汇的跨窗类别漂移，而不是仅提高重复融合。

论文的可辩护贡献因此应写成“**面向高分辨率单图 OV-RSIS 的、由空间拓扑与实例关系
路由的记忆管理**”，而不是泛称“将滑窗接入 SAM3 memory”。必须以 M1 为直接对照，并
额外报告不同滑窗遍历顺序的稳定性；若 M2 不优于 M1，图就没有被证明具有独立价值。

### 10.3 重要收敛：滑窗不是我们的记忆机制（2026-09-10）

若主方法是“蛇形扫描重叠滑窗，并把最近窗口依次送入 SAM tracker 的 FIFO memory”，
则与 OmniSAM 的**核心机制实质撞车**；即使再在输出端添加图，也很难摆脱“OmniSAM 式
伪视频记忆的增量改造”的审稿判断。因此这条路线只应保留为 M1 强基线，不能作为论文
的中心叙事。

本项目更合适的定义是：**滑窗是受显存约束的局部观测器；图结构空间实例库才是记忆。**
它不随“先处理哪个窗口”线性推进，不把最近窗口默认视为最相关，也不把整条滑窗序列
写进 FIFO。全图可按任意顺序完成第一次观测，图依据全局坐标、重叠、对象身份和质量
建立可随机访问的空间记忆；对任一待细化对象，只取回空间和语义上相关的少数证据。

相应的主 pipeline 应改为两阶段、遍历顺序无关的形式：

```text
I + 开放 prompts
  ↓
R1. 独立的滑窗 reconnaissance pass：SAM3 detector 对每 tile 提出候选观察
    （滑窗只解决 FoV/显存；不使用 FIFO tracker 继承）
  ↓
R2. 全图图化与记忆固化：以跨窗一致性建立 instance tracklet；将可靠观察编码成
    坐标感知的对象记忆，保存其 masklet、外观、环带上下文、文本证据与不确定性
  ↓
R3. Query-specific graph retrieval：对一个模糊候选，检索同一 tracklet 的其它视角、
    空间相关上下文和直接竞争假设；排除该候选自身，避免自证据回灌
  ↓
R4. SAM3 refinement：将检索到的少量 anchor 以 memory-token adapter 或
    visual/mask prompt 的方式注入 SAM3；图也可要求 detector refresh，而非直接投票改类
  ↓
R5. 全图实例融合与 unknown-aware 输出
```

这使“图 + SAM3 memory”的技术切口明确为：图在 R2 决定什么可编码为 memory record，
在 R3 决定当前 query 从全图的哪几条 record 读取，在 R4 决定读出的记录如何成为 SAM3
的条件；需要时用空间相对坐标编码替换/补充原生 tracker 的时间位置编码。最后一项是
可训练 adapter 的研究问题，不能假装为冻结 SAM3 已有接口；在冻结版实现中可先使用
SAM3 已支持的 visual/mask prompt 作为等价、可复现的 readout。

与 OmniSAM 的可检验划界是：OmniSAM 为 `patch sequence → FIFO memory attention`，
本方法为 `all-tile observations → order-invariant instance graph → query-specific sparse
retrieval → SAM3 conditioning`。因此除了同预算 FIFO 对照外，必须进行窗口遍历顺序
置换测试：若输出随扫描顺序显著变化，说明实际仍退化成序列记忆，不能成立为图空间记忆。

### 10.4 SAM3 空间坐标适配与轻量 adapter：现成边界（2026-09-10）

结论：**有可直接复用的接口和代码骨架，没有可直接复制的“SAM3 全局空间图记忆”
实现。** 不能把这部分写成低风险 glue code。SAM3 官方开源 tracker 的
`sam3/model/sam3_tracker_base.py` 已给出三个可改接口：

1. `_encode_new_memory`：把当前视觉特征和预测 mask 编为 `maskmem_features` 与
   `maskmem_pos_enc`；可原样复用为对象/窗口 memory record 的低层编码器；
2. `_prepare_memory_conditioned_features`：收集被选 memory，拼接 `prompt` 和
   `prompt_pos` 后进入 tracker transformer；目前选择逻辑是时间上最近的 conditioning
   frame 与 FIFO 非条件帧，可替换为图检索返回的 tile/tracklet record；
3. `maskmem_tpos_enc` 与 `_get_tpos_enc`：分别给 mask-memory slot 和 object pointer
   加一维时间位置编码；这是空间关系 adapter 的明确插入点。

但“把 tpos 换成 tile 坐标”仍不充分。原 tracker 的当前 token 和 memory token 都有
各自**局部窗口坐标**，且 memory cross-attention 中还使用二维 RoPE；若只额外加一个
tile-level `(dx,dy)` embedding，注意力内部仍会把两个 tile 的相同局部像素位置误认为
对应位置。真正的空间版本至少要为 query-token 与 memory-token提供一致的全图坐标，或
在 cross-attention 中实现相对全局坐标 bias/全局 RoPE；这才是 adapter 的实质技术边界。

可借鉴的公开代码按风险分三档：

| 路线 | 可参考实现 | 能直接复用什么 | 不能声称什么 |
|---|---|---|---|
| FIFO 强基线 | OmniSAM（SAM2） | patch 序列、memory bank 开关、滑窗基线流程 | 不是我们的主方法，且不是 SAM3/OV 实例任务 |
| 外部图检索→prompt（推荐第一版） | SAM-I2V 的 memory-as-prompt；Memory-SAM 的 retrieval-to-prompt；SAM3 visual exemplar 接口 | 图选 anchor、聚合少数记忆、生成 mask/visual prompt；不改 native attention | 这叫 graph-conditioned prompting，不应叫“改造 SAM3 原生 memory attention” |
| 原生空间 memory adapter（研究版） | SAM3 tracker 官方源码、SAM2/SAM-I2V 的 memory reader/writer 结构 | 保留 memory encoder 与 transformer 容器，替换 selection、位置编码与坐标注意力 | 没有现成可直接跑的实现；需训练并证明空间对齐有效 |

Spatial-SAM 提供了“空间任务不应直接继承顺序式 logit memory”的方法论：它用预计算
SDF 替换记忆，并用双向邻域且排除自身以避免误差自耦合；截至本次核对，其项目页声明
代码将在接收后公开，不能当作可拷贝实现。FSS-SAM3 则是直接红线：其跨图 support/query
伪视频 memory 路线失败，成功的 training-free 通道是把图像拼入统一 canvas 后走
visual-exemplar/self-attention。因此“图检索到跨窗锚点后直接喂 tracker”的假设必须先做
小规模可行性 probe，不能直接作为主线承诺。

建议的技术路线因此调整为：

```text
Phase A（可实现、低风险）
图检索 → 坐标变换后的 anchor mask/crop → SAM3 visual/mask prompt 或统一 canvas
→ 验证 graph retrieval 是否比 FIFO/随机 anchor 更好

Phase B（只有 A 有正信号后）
冻结 SAM3 主干；训练 graph retriever + spatial relation MLP，替换最近帧选择；
memory record 加 {全图 token 坐标、tile origin、scale、overlap、edge type}

Phase C（论文的 native-memory 版本）
把 tracker memory cross-attention 的局部 RoPE/时间 slot 编码改为全图相对空间编码，
再训练小 adapter；必须做全局坐标 on/off、图检索/FIFO、遍历顺序置换的消融。
```

因此当前不应许诺“只写一个小 adapter 就能让 SAM3 适配空间图”。第一篇的稳妥主张是
图检索控制 SAM3 的**条件输入**；只有 Phase C 通过后，才将贡献升级为“graph-controlled
native spatial memory”。

### 10.5 工程收敛版：图索引的跨窗几何提示传播（2026-09-10，建议立项）

鉴于原生空间 memory adapter 要同时改选择器、时间编码、局部 RoPE 与训练协议，第一版
应**完全砍掉**该路线：不修改 SAM3 tracker、memory encoder、RoPE 或 attention；不引入
GNN/消息传递、MLLM、跨图长期库或学习式空间 adapter。把“记忆”收敛为每幅大图内一个
有限的、可审计的**实例证据缓存**，图只负责索引和选择，不计算端到端图表征。

该版本可只用当前已经验证通过的 SAM3 图像 API：`set_text_prompt` 后
`add_geometric_prompt(state, box, label=True)` 可以组合文本概念和正框提示。因而图检索的
readout 不必伪造跨图 visual exemplar，也不必接入 tracker；它把邻窗中可信的对象框映射
到当前 tile 坐标，作为 SAM3 的正几何 prompt，要求模型在**当前真实图像**上重新产生 mask。

```text
Pass 1：每 tile 独立以文本 prompt 运行 SAM3 detector
  → {global mask / global box / score / presence / tile id}
  ↓
稀疏实例图（纯规则、无 GNN）
  tile-overlap 边 + 跨窗 global-mask IoU 的同实例边
  仅保留一个实例在其它 tile 中的高质量 anchor；不使用共现边和全连接边
  ↓
Pass 2：仅处理“跨窗重复且质量低/边界截断”的 query
  → 从同一 tracklet 取一个非自身 anchor
  → 将 anchor global box 裁剪并映射为 query-tile 的归一化 cxcywh
  → text prompt + positive geometric prompt 重跑 SAM3 image processor
  ↓
将重跑 mask 回投全图坐标，常规 mask fusion / NMS 输出
```

这不是“改 SAM3 memory”，准确命名应为 **topology-guided cross-window prompt
propagation** 或 **graph-indexed instance evidence retrieval**。其轻量创新点是：与
OmniSAM 的序列 FIFO 相比，使用全图重叠拓扑和实例共指关系选择**哪个**邻窗证据应成为
SAM3 prompt；SAM3 在当前窗口重新分割，而非图直接重排类别分数。该定义刻意避免重演
v2 的候选互相抬分。

最低可行验证必须先于大规模实现：在少量有重叠的高分辨率图上，比较 (i) 独立 tile，
(ii) 随机重叠邻窗框提示，(iii) 图选同一实例 anchor 框提示；报告 anchor 到 query 的
几何映射成功率、边界 IoU/全图实例 AP、误提示率和耗时。若 (iii) 不超过 (ii)，图检索
本身无价值，应停止，而不是叠加上下文、类别边或训练模块。

当前 SCORE 的常规 512 级单图评测只适合评估候选与开放词汇分类，不足以单独证明跨窗
记忆；该方法需要另设真实大图/重叠裁剪协议，并保持每张测试图为独立 episode。长期的
空间 memory adapter 仅在这个轻量版本出现清晰正信号后才重新讨论。

### 10.6 现有数据上的低成本可否证探针（2026-09-10，建议先做）

现有 S2.3 实测已给出限制：SCORE 三个主测试集原图为 NWPU 512²、SOTA 1024²、FAST
600²；使用 1024 窗口/768 stride 时整图、分块和滑窗 mAP 几乎相同。因此不得把当前
SCORE 主表直接包装成“大图空间记忆提升”的证据，也不应为制造滑窗而回改主评测。

但既有 COCO 实例标注足以运行一个**双窗口受控探针**，它测的不是泛泛 mAP，而是这条
因果链是否存在：`重叠邻窗的可靠观察 → 图选同一对象 anchor → 正框提示 → 当前截断
视野中的 mask 恢复`。推荐在 iSAID train（人工 mask，开发用）固定抽样；设计冻结后再
在 NWPU 的独立保留子集复验。GT 只用于采样分层和离线打分，绝不能在 anchor 选择或
推理时使用。

```text
对每个 GT 实例构造两个重叠 crop：
  A = anchor view，目标大部分可见；Q = query view，目标位于窗边且部分截断
       ↓
Pass 1：A、Q 都仅用该类别文本运行 SAM3，得到预测候选
       ↓
在全图坐标系建仅含 A/Q 候选的微型图：overlap + 预测 mask IoU + 质量
       ↓
Pass 2：对 Q 中模糊候选，图从 A 选择一个非自身高质量 anchor；将其预测框
映射到 Q 坐标，以 text + positive box 重跑 SAM3；不匹配则 abstain
       ↓
将 Q 的重跑结果同 Q-only 原结果作逐实例及整图比较
```

探针必须有四个互补组，不能直接从“有 improvement”跳到“图有效”：

| 组别 | 用途 | 使用 GT 的位置 |
|---|---|---|
| G0：Q text-only | 当前被截断视野的基线 | 仅离线评分 |
| G1：Q + **GT box** | 几何 prompt 是否有足够上界收益；若无收益，立即停止 | box 仅作为 oracle prompt |
| G2：Q + 随机重叠邻窗预测框 | 排除“任意多一个正框都有效” | 不用 GT 推理 |
| G3：Q + 图选预测 anchor 框 | 真正的最小方法 | 不用 GT 推理 |

先报告三个中间判据，再花钱跑全图 AP：

1. **anchor 纯度**：G3 所选 anchor 与 query GT 是否实际为同一实例（IoU≥0.5）；
2. **条件恢复率**：在 G0 未匹配而 G3 anchor 正确的样本中，G3 是否把 IoU 拉到≥0.5；
3. **净伤害率**：G0 原本正确而 G3 因错误提示变差/变错的比例。

最终再报告同一批 query 的 instance IoU、AP50 与 AP@[.5:.95]，并按“窗边截断”和
“非窗边”分层。最小 GO 逻辑应是：G1 显示 prompt 上界有价值，G3 在 anchor 纯度足够时
优于 G2，且净伤害受控；任一环节失败，停止在该环节修正，不增加图边或训练模块。

这项 probe 只需重用现有 `inference_modes.py` 的 crop→全图坐标回投、
`Sam3Processor` 的 text/box 接口和 `score_eval.py` 的 COCO 评测；新增工作限定为
crop pair 生成、预测 mask IoU 关联、box 坐标变换和四组结果记录。它不需要改 SAM3，
也不需要下载新数据。若 probe 通过，才应另找真实 >2048px 遥感图做最终外部验证；
若不通过，应放弃该跨窗 prompt 路线，而非把 SCORE 的小图结果误作支持。

### 10.7 大图开放词汇数据集选择（2026-09-10）

当前 SCORE 主测试集不适合验证跨窗机制，但并非没有替代数据。应按“任务是否真开放词汇”
与“是否有足以做实例级跨窗评测的原生大图 mask”分级，不能把语义类数据的成功外推成
实例图记忆成功。

| 候选 | 大图与标注 | 与本方案的关系 | 建议 |
|---|---|---|---|
| **OVEarth-Bench**（arXiv 2026，Apache-2.0） | 520 张新采集 GeoTIFF，宽 692–4713px，约 3.28GB；590 人工复核 mask、4810 水平/旋转框；172 类、1346 词表、3235 个开放词汇 query（含 1067 正/2168 负） | 同时具备原生大图、类别词 query、实例多边形/框与负 query；可测试 prompt 传播收益和错误 anchor 是否增加幻觉 | **首选外部 probe/补充评测**；mask 数较少，不能单独替代 SCORE 主表 |
| **NWPU-Refer**（arXiv 2025） | 15003 张 1024–2048px 图，49745 人工目标；单/多目标和无目标指代 | 大图、实例 mask、无目标能力都强；可把类别级或多目标 query 作为开放概念近邻测试 | **首选规模验证**，但主任务是 referring，不应写成标准 OV-RSIS 主表 |
| LandDiscover50K / OVRSISBench(V1/V2) | 大规模开放词汇**语义** mask；LD50K 51,846 图、40 类、约 70.6GB，来源图宽约 400–1200；V2 有 170K 图/128 类 | 开放词汇协议强，但没有独立实例身份；不能评估“同一实例跨窗 anchor”或实例 AP | 只用于语义泛化/下游补充，不作为当前最小方法首选 |

推荐的低成本路径是：先在现有 iSAID/SCORE 做受控双窗口机制 probe（不对外声称大图结论），
若 G3>G2 成立，再下载 OVEarth-Bench 做真实大图的开放词汇正/负 query 验证；最后若需要
规模与多对象/无对象论证，再接 NWPU-Refer。这样总是先验证“图选 anchor”这一因果机制，
再扩大数据，而不是先引入 70GB 语义数据或重写任务协议。

注意 OVEarth-Bench 是很新的 arXiv benchmark，发表状态与官方评测工具仍应在正式实验前
复核；其 590 mask 与 4810 boxes 数量不同，mask AP 与检测/框指标需分开报告。下载或接入
前不得把它与现有 SCORE COCO instance protocol 混写为同一主表。

## v3 终局与 v4-S0 止损（2026-10-26）

两条主线在同一天按预注册协议给出最终答案，全部产物已 commit。

### v3 冻结验证（关账，负结果/中性）

冻结 β=0.5、δ=0、λ=2，在双重排除（dev 15 组 + T1 探针 242 组）的 146 张
held-out iSAID 源图上一次运行（`notes/reports/v3-frozen-eval-results.md`）：

| 变体 | segm mAP | 相对 B0 |
|---|---|---|
| B0 SAM3 单调分 | 0.2115 | — |
| B1 独立 CLIP 融合 | 0.2180 | +0.65 pt |
| B2 空间相对惩罚 | 0.2208 | +0.93 pt |
| B3 非空间类别对比 | 0.2272 | +1.57 pt |

逐图配对 bootstrap：B2−B1 均值 −0.001（CI 含 0）→ 按判据树停止相对惩罚；
B3≥B2 复现 → 空间图主张关闭；全部增量 CI 含 0 → 不进 T3。执行 trail：
首跑被独立审计拦截（抽样漏排 T1 组，47% 样本污染），双重排除后重跑；
score 阶段修复两个 pycocotools 坑（loadRes 原地补 bbox 的对象污染、
maxDets 单元素 vs summarize 硬编码索引）。dev 的 +0.28 pt 点估计在
held-out 复现但不显著——机制信号（T1 的 143:1 不对称）存在，数据集级
mAP 收益不可确认。

### v4-S0 C0 统计（TG-CWP 止损）

路线 A 获批后跑 DOTA-v1.5 val 100 图 C0（独立 1024/200 tiles + 全局逐类
NMS 融合，2.2 GPU 时；`notes/reports/v4-s0-c0-verdict.md`）：

- C0 全图 segm mAP 0.0965；GT 命中率 68.0%；融合重复率仅 1.33%。
- **漏检 2,052 个中仅 5.12% 在任一 tile 可见（融合前）；oracle 正框恢复
  上限 = 全部 GT 的 1.64%**（严格完整观察 1.57%）。
- **94.9% 的漏检在所有 tile 都无响应**——基座检出瓶颈，任何跨窗传播
  （C1/C2/C3）都无法触及；截断空间（摸底）也仅 0.4–0.7%。

判定：oracle 天花板 ~+1–2 mAP pt、实测严格更低，低于本项目机制主张
门槛（实测 +1 pt）；S0 未预注册数值阈值（设计缺口已如实登记），但结论
对该缺口不敏感。**TG-CWP 在 S0 停止，C1/C2/C3 不进入实施。**
