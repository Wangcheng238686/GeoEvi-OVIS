# v4-S0 C0 统计与准入判定（TG-CWP）

> `sam3_ovis/eval/v4_s0_c0_run.py`（推理）/ `v4_s0_c0_analyze.py`（分析）；

## 1. 设置

DOTA-v1.5 val 原图 100 张（seed 20261025，优先含非 difficult 实例），
tile=1024 / overlap=200（锚点逻辑与摸底一致），SAM3 text-only 逐 tile
16 类，pool floor 0.05；C0 = 全局坐标逐类 mask NMS（IoU≥0.5）融合。
GT = OBB polygon RLE，difficult 剔除（落其上的预测计 FP，登记口径）；
prompt 用原始连字符类名（不改写，登记口径）。

## 2. 结果

| 统计 | 数值 |
|---|---|
| [a] C0 全图 segm mAP / AP50 / AP75 | 0.0965 / 0.1973 / 0.0764 |
| [b] GT 命中率（IoU≥0.5 同类，非互斥） | 68.04%（4,368/6,420） |
| 漏检总数 | 2,052 |
| [c] 漏检中**任一 tile 可见**（融合前） | **5.12%**（其中完整未截断观察 4.92%，仅截断观察 0.19%） |
| [d] oracle 正框恢复上限 | /漏检 **5.12%**；/全部 GT **1.64%**（严格完整 tile 观察 1.57%） |
| [e] 融合后重复率 | 1.33%（58/4,368） |
| 融合前→后候选数 | 121,927 → 69,448 |
| 边界子集（cross/corner GT） | 合计 22 个：hit 9/22，重复 1 |

结构性事实：**94.88% 的漏检在所有 tile 中都不可见**（pool floor 0.05 下
SAM3 对这些实例零响应）——它们是基座检出问题，任何跨窗传播机制都无法触及。

## 3. 准入判定

对照 design-v4.0 §5 的登记逻辑（"作用空间不足则停止，不以人为切得更碎
制造问题"）：

1. **截断空间**（摸底）：跨窗实例仅 0.4–0.7%——微小。
2. **邻窗漏检差异空间**（本报告，route A 要量的数）：oracle 上限
   **1.64% 全部 GT**（严格口径 1.57%）。任何真实方法（C1/C2/C3）的收益
   **严格低于 oracle**：召回上限 68.0%→69.6%，即使全部完美恢复、mask
   与分数无损，mAP 增益的数学上限约 +1~2 pt，还要被传播引入的重复/错误
   抵消（现有融合重复率已仅 1.33%，去重轴也没有空间）。
3. 本项目对机制主张的既有门槛是**实测 +1 mAP**（v3-T3 登记）；一个
   oracle 天花板仅 ~+1–2 pt、实测必然更低的机制无法满足该门槛。
4. 登记诚实性说明：S0 未预注册数值阈值（设计缺口，如实记录）；本判定
   依据是 oracle 上限与既有机制门槛的量级比较，结论对该比较不敏感
   （即使门槛放宽到 +0.5 pt，实测收益仍大概率不达）。

**判定：TG-CWP（v4 主线）在 S0 止损。** C1/C2/C3 对照链不进入实施。
路线 A 的作用即在此：以 2.2 GPU 时买断了整条 pipeline（预计数十 GPU 时
+ 数周工程）的沉没风险。

## 4. 口径备忘（解读边界）

- mAP 0.0965 的绝对值受三重压低：连字符 prompt 未改写、difficult 计 FP、
  DOTA 类不在 SAM3/评测生态常规内——但这不影响判定：[c]/[d] 是跨 tile
  相对可见性统计，与绝对检出水平近似解耦；召回提高只会让"全部 GT"分母
  口径的 1.64% 更小（missed 池缩小而 visible 池不增）。
- [b] 口径为非互斥匹配（COCOeval 之外独立计算），不受 maxDets=100 截断
  影响；[a] 受 maxDets 影响（密集图候选上万），登记为 C0 下界。
- 边界子集（cross/corner）样本量 22，过小不做单独主张。
