## 0. 协议偏差登记（如实）

实现按**组级 val 全集**（18 个 val 组的全部 117 切片 / 6,721 GT）评估，
而非协议字面的"46 图缓存子集"——46 图本是 G2a 缓存的人工截断，117 图
的组级隔离同样完整（val 组从未参与任何开发/选参）。样本量更大、配对
bootstrap 内部一致；B0 的 mAP（0.1787）与 g4a 的 0.2230 差异即来自
子集不同。判定有效性不受影响。

## 2. 判定（按协议 §3）

COMBO−B0 = **+8.68pt ≥ +3pt 且 CI 不含 0 → 免费杠杆构成实质新基线**，
R1 在新基线上重立项。归因：
1. **L1（prompt 格式）是支配杠杆**：单独 +8.16pt。下划线分词伪影从 P0
   起压低了本项目所有绝对数字（机制对比全部是同 prompt 内配对，内部
   Δ 不受影响；但项目全景诊断被系统性偏置）。
2. L2（低分带候选）+2.65pt 显著为正——子阈值候选携带真实排序价值，
   floor 0.05 是过度截断（与审计②"90.4% 漏检有子阈值覆盖"一致）。
3. L3（1344）单独无效（+0.14 n.s.）——该设置下分辨率不是 mAP 瓶颈
   （审计②的 +16.5pt 是召回口径、特定困难图；不矛盾）。
4. **代价结构**：COMBO 的 same-class 召回降至 31.8%（any-class 95.3%）
   ——恢复的候选大量错类；FP/图 升至 290。分类通道（真实 ~2.2pt）
   与 FP 排序成为新基线上的主要剩余损失，正是 R1（定位+域适配）与
   分数校准的用武之地。

## 3. 执行 trail

- L3 首跑崩溃于全局块 RoPE 缓存（1008/14=72 固化）——复用审计②的
  `set_grid`（g4b_gpu_probes）重建 96×96 网格后通过（窗口块不受影响，
  方案已有先验验证）。
- 生成 5 臂 × 117 图 ≈ 15 分钟（GPU0 共享卡，autocast bf16）。

## 4. 对项目叙事的最终修正

"全线失败、无路可走"不成立：**管线自带 +8.7pt 的免费空间，其中 94%
来自一个一行代码的 prompt 修复**。五条机制止损经独立审计维持（它们
的配对结论不受 prompt 影响），但"失败"的正确归因是：全部火力对着
~2pt 的分类通道，而 8pt 的格式伪影、3pt 的阈值截断、FP 排序从未被
触碰。方向性结论：**先免费杠杆、再校准排序、最后微调**——R1 以
COMBO（mAP 0.2700）为新基线重立项。
